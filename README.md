# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

### Слой коммуникации
Класс отвечает за взаимодействие приложения с сервером. Он использует композицию: внутри него хранится экземпляр API-клиента, через который он делает запросы. Обеспечивает получение списка товаров и отправку данных заказа.

### AppApi (Слой коммуникации)
Зона ответственности: Загрузка каталога товаров с сервера. Отправка оформленного заказа на сервер. Преобразование данных между форматом сервера и внутренними моделями приложения.

Конструктор: constructor(api: Api)

Описание: Внутренняя ссылка на объект, реализующий интерфейс IApi. Через него выполняются все HTTP‑запросы. Не доступен снаружи класса.

## Класс CatalogModel
Назначение: Хранение и управление списком товаров каталога, выбор товара для просмотра. Отвечает только за данные и бизнес‑логику над ними (без запросов к серверу). Загрузка данных происходит извне (через saveProducts).

Конструктор: constructor(private events: IEvents) {}

Метод: setItems(items: IProduct[])
Параметры: items: IProduct[] — новый список товаров
Возвращаемое значение: void
Описание: Заменяет текущий список товаров на переданный. После этого отправляет событие catalog:changed, чтобы другие части приложения (например, представление) узнали, что каталог обновился.

Метод: getItemById(id: string)
Параметры: id: string — идентификатор товара
Возвращаемое значение: IProduct | undefined

Возвращаемое значение: IProduct[]
Описание: Возвращает текущий массив товаров. Важно: возвращает ссылку на внутренний массив. Если снаружи его изменят, это повлияет на состояние модели.

Метод: setSelectedItem(item: IProduct)
Параметры: item: IProduct — выбранный товар
Возвращаемое значение: void
Описание: Устанавливает товар как текущий выбранный и отправляет событие catalog:selected. Предполагается, что item уже есть в каталоге.

Метод: getSelectedItem(): IProduct | null
Параметры: -
Возвращаемое значение: IProduct | null
Описание: Возвращает выбранный товар или null, если ничего не выбрано.

## Класс BuyerModel
Назначение: Хранение данных покупателя и их валидация перед оформлением заказа. Не отправляет данные на сервер — только проверяет и отдаёт готовый объект.
Конструктор: constructor(private events: IEvents) {}

Метод: setData(data: Partial<IBuyer>)
Параметры: data: Partial<IBuyer> — частичный объект с данными покупателя

Описание: Обновляет только те поля, которые переданы в объекте data. Для каждого поля проверяет !== undefined, чтобы не затереть существующие значения пустыми строками или null. После обновления отправляет событие customer:changed.

Метод: getData(): IBuyer
Параметры: -
Возвращаемое значение: IBuyer
Описание: Возвращает полный объект с текущими данными покупателя. Используется, например, чтобы передать данные в форму заказа или отправить на сервер.

Метод: clear(): void
Параметры: -
Возвращаемое значение: void
Описание: Очищает все поля: адрес, email, телефон — в пустую строку, способ оплаты — в null. 
Затем отправляет событие customer:changed.

Метод: validate(): TBuyerErrors
Параметры: -
Возвращаемое значение: TBuyerErrors
Описание: Проверяет обязательные поля. Возвращает объект с ошибками: ключи — поля, значения — сообщения об ошибках. 

### Типы данных приложения

## IProduct
Товар в каталоге и корзине.

Поля:
id: string;
- Уникальный идентификатор продукта (строка, например UUID или артикул).
description: string;
- Подробное описание товара (состав, особенности, характеристики).
image: string;
- Ссылка на изображение.
title: string;
- Название товара, отображаемое в карточке и списке.
category: string;
- Категория товара (используется для цветового тега и фильтрации).
price: number | null;
- Цена товара в условных единицах; null — если товар недоступен или цена не указана.

## TPayment
Допустимые типы оплаты.

## IBuyer
Данные покупателя для оформления заказа.

Поля:
email: string;
- Электронная почта для связи и отправки чека.
phone: string;
- Номер телефона для подтверждения заказа.
address: string;
- Адрес доставки.
payment: TPaymentModel;
- Выбранный способ оплаты.

## IForm
Базовое состояние любой формы (валидность и ошибки).

Поля:
valid: boolean;
- Флаг валидности формы: true, если все обязательные поля заполнены и корректны.
errors: string[];
- Список сообщений об ошибках валидации для отображения пользователю.

## IOrderForm
Поля формы оформления заказа (адрес и оплата).

Поля:
address: string;
- Адрес доставки, введённый пользователем.
payment: TPayment;
- Способ оплаты, выбранный пользователем.

## IContactsForm
Поля формы контактов (email и телефон).

Поля:
email: string;
- Email пользователя.
phone: string;
- Телефон пользователя.

## IOrderData
Данные для отправки заказа на сервер. Расширяет IBuyer, добавляя состав корзины и итоговую сумму.

items: string[];
- Массив ID товаров, которые входят в заказ.
total: number;
- Итоговая сумма заказа (рассчитывается на клиенте или приходит из модели корзины).

## IProductsResponse
Ответ сервера со списком продуктов (пагинация + данные).

Поля:
total: number;
- Общее количество товаров в каталоге (для пагинации).
items: IProduct[];
- Массив продуктов текущей страницы.

## IOrderResponse
Ответ сервера после успешного создания заказа.

Поля:
id: string;
- ID созданного заказа в системе.
total: number;
- Итоговая сумма, подтверждённая сервером.

## ICardGeneral
Базовые данные для любой карточки товара (общие поля).

Поля:
title: string;
- Заголовок карточки (название товара).
price: number | null;
- Цена товара; null — если цена не указана или товар недоступен.

## IBasketCard
Данные карточки товара в корзине (Basket).

Поля:
index: number;
- Индекс товара в корзине (нужен для удаления/обновления по позиции).

## ICardCatalog
Данные карточки товара в каталоге

Поля:
category: string;
- Категория товара (для цветового бейджа).
image: string;
- Путь к изображению товара.

## ICardPreview
Данные карточки предпросмотра товара (Preview). Содержит расширенную информацию и состояние кнопки действия.

Поля:
category: string;
- Категория товара.
description: string;
- Описание товара.
image: string;
- Путь к изображению товара.
inBasket?: boolean;
- Признак наличия товара в корзине.
buttonText: string;
- Текст на кнопке действия («В корзину», «Удалить» и т.п.).
buttonDisabled: boolean;
- Состояние кнопки: true — кнопка заблокирована, false — доступна для клика.

### Презентер (Presenter)
Презентер реализован в файле src/main.ts и содержит всю логику приложения. Он связывает модели данных и представления через обработку событий.

## Ответственность презентера:
Инициализация — создание экземпляров всех компонентов (моделей, представлений, API)
Обработка событий — подписка на все события и выполнение соответствующих действий
Координация — связывание моделей и представлений, обновление данных и отображения

## Перечень событий
Событие: catalog:changed
Описание: Перерисовывает галерею: создаёт карточки каталога из актуального списка товаров и передаёт их в Gallery.

Событие: card:selected
Описание: Находит выбранный товар по id в каталоге и сохраняет его как выбранный элемент в CatalogModel.

Событие: catalog:selected
Описание: Открывает модальное окно с превью выбранного товара: заполняет поля карточки и определяет текст/состояние кнопки в зависимости от цены и наличия в корзине.

Событие: preview:submit
Описание: Обрабатывает клик по кнопке в превью: если товар в корзине — удаляет, если нет — добавляет, затем закрывает модальное окно.

Событие: basket:open
Описание: Открывает модальное окно с содержимым корзины.

Событие: basket:delete
Описание: Удаляет товар из корзины по id (срабатывает при клике на кнопку удаления в карточке корзины).

Событие: basket:changed
Описание: Обновляет корзину: пересчитывает счётчик в шапке, перерисовывает список карточек, обновляет итоговую сумму и доступность кнопки оформления заказа.

Событие: basket:submit
Описание: Открывает форму заказа (Order) внутри модального окна, подставляя текущие данные покупателя.

Событие: customer:changed	
Описание: Обновляет обе формы (Order и Contacts) актуальными данными покупателя, запускает валидацию и выводит ошибки (или снимает их), управляет доступностью кнопок.

Событие: order:payment
Описание:	Записывает выбранный способ оплаты в модель покупателя.

Событие: order:address
Описание: Записывает введённый адрес доставки в модель покупателя.

Событие: contacts:phone
Описание:	Записывает введённый номер телефона в модель покупателя.

Событие: contacts:email
Описание:	Записывает введённый email в модель покупателя.

Событие: order:submit	
Описание: Переход с формы заказа на форму контактов: заменяет контент модального окна на Contacts.

Событие: contacts:submit	
Описание: Отправляет заказ на сервер, при успехе показывает экран Success, очищает корзину и данные покупателя, сбрасывает обе формы.

Событие: success:close
Описание: Закрывает модальное окно с экрана успешного оформления заказа.
